ScaleGlide AI

Feb 2024 – Feb 2025

GlenFlow portfolio
Architecture & team leadership

4 client pilots delivered

AI workflow orchestration

A new pilot should need
a new scenario.

Each client needed a different chain of AI requests, checks, and outputs. I designed a Node.js DSL and built the complete JumpStart core so these workflows could be assembled from reusable operations.

The constraint

Model responses were unpredictable. Client logic varied, and each interface belonged to its client. Reusing a previous pilot was rarely practical.

The decision

Move branching, parallel requests, validation, and formatting into an execution engine. Let a prompt engineer edit scenarios through the interface without a redeploy.

~4 → ~2 weeks

Typical delivery time for a working client pilot. Reusable orchestration reduced repeated implementation and debugging across four pilots. Timing is approximate.

More about the architecture and my role +

I led a six-person team and worked across requirements, architecture, implementation, and integration. I designed the DSL and implemented the full JumpStart core underpinning GlenFlow Engine.

The engine used cross-model response validation and output-format checks. When a request failed, the scenario could retry, adjust model parameters, or use another model. Bounded, delayed retries and email status updates helped keep clients informed when processing could not finish immediately.

A dedicated prompt engineer wrote scenarios using the engine’s command reference, with my support throughout. The core handled branching, parallel work, intermediate checks, formatting, and JSON output; scenario changes no longer required writing and debugging that control flow again.

COR-Software

Mar 2025 – Present

Fractional · Remote
Solution Architect & Lead Engineer

Private beta

ERP & finance

Automate the routine.
Make import decisions visible.

As the primary application engineer, I’m building a finance and ERP platform for multiple businesses — from business analysis and architecture to implementation, testing, and release validation.

The constraint

Bank formats and identifiers differ. Daily statement downloads take time, while beta users need to see how incoming records will be parsed and classified.

The decision

Use bank APIs where available and separate bank-specific parsing from shared finance workflows. Keep preview/commit imports for validation and as a fallback.

Fewer routine manual steps, with a reviewable fallback. API integrations remove daily statement downloads where supported. The private beta serves multiple businesses and processes hundreds of monthly transactions.

More about the architecture and my role +

The application covers multi-company cash-basis accounting, accounts payable and receivable, inventory, fleet and fuel, assets, CRM, and document workflows. Access rules are enforced on the server, with audit trails and recovery support.

Each bank has its own parsing schema. Duplicate detection uses a payment’s unique identifier when available, or a configured combination of fields when it is not. Description rules help assign categories automatically.

The preview shows parsed values, categories, account assignments, duplicate matches, and records that will be restored from deleted entries. This helps us validate behavior during beta and keeps a usable fallback when automatic retrieval is unavailable.

I own the application architecture and implementation, work with DevOps, mentor a trainee, and maintain automated checks with Playwright and unittest.

03

OxyDial

Mar 2023 – Nov 2024

GlenFlow portfolio
Architecture & team leadership

Research & validation

Measurement processing & cloud SaaS

Better measurements need
a way to check the result.

I led a six-person engineering team and owned the architecture and delivery of a cloud platform for oxygen–hemoglobin equilibrium curve testing, including work on numerical processing.

The constraint

Measurement noise and reagent variation affected the resulting curve. Processing needed to improve accuracy while keeping calculation time practical.

The decision

Reduce noise, account for reagent coefficients, and tune iteration counts. Investigate fitting methods and check the results against independent references.

Processing
Smooth & correct

Reduce measurement noise and incorporate reagent coefficients.

Investigation
Reconstruct the curve

Explore Levenberg–Marquardt fitting toward a sigmoidal representation.

Validation
Compare P50 / P90

Check deviations against manual calculations, reference results, and other software.

↗

Improved curve accuracy and faster calculation. Numerical work reduced errors and refined iteration counts. The web platform was deployed in the company’s research and validation environment.

More about the research and delivery +

I investigated Levenberg–Marquardt fitting as part of reconstructing a sigmoidal curve from smoothed measurements. This was research into a fitting approach. We used visual overlays during investigation and checked deviations in calculated P50 and P90 against manual calculations, reference results, and other software.

The platform also included automated device-data ingestion, cloud storage and backup, analytical dashboards, reports, CSV exports, audit trails, and remote research collaboration.

Its web and numerical-processing components contributed to a broader medical measurement process for which the company filed a patent application.
